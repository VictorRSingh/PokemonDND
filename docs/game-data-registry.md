# Game data registry
Construct `createGameDataRegistry(rawSpecies, rawMoves, rawNatures)` once per dataset version and reuse the returned instance. The caller loads JSON; no filesystem, React or database dependencies. Strict validation rejects unexpected issues before construction. Normalization currently runs twice (validation and construction); no per-lookup normalization. Returned definitions, arrays and nested objects are frozen at runtime. TypeScript readonly contracts apply to definitions.

Lookups accept canonical IDs or names normalized to IDs. Unknown direct lookups return undefined. Species-dependent queries reject unknown species. Pokédex number returns all forms. `getEvolutionChain` returns the starting species and reachable descendants, not ancestors or eligibility decisions. `getLearnableMoves` returns level-qualified learnset entries, including explicitly unavailable moves; defined metadata does not imply executable combat handlers. `getSpeciesAbility` checks species membership and selects species-specific text where present. `filterSpecies` filters base level and rating, not encounter balance. No TM or egg move eligibility is inferred. The five documented TM exceptions and two unavailable moves remain visible in validation. No global cache: callers retain the registry instance.

Run `node scripts/validate-game-registry.mjs` from project root. An optional dataset directory argument overrides public/data.
