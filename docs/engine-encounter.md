# Encounter lifecycle (5.5)
Pure immutable transitions: createEncounter(id, kind, rules, seed), registerCombatant(state, combatant, expectedVersion), startEncounter(state, expectedVersion, manualRolls?), spendTurnResource, spendMovement, spendReaction, endTurn, pauseEncounter, resumeEncounter, completeEncounter. Every successful transition increments version; rejected transitions throw without changing state. Start returns initiative roll records separately for logging. Shared slots use trainer Dexterity even when trainer participation is disabled; wild unowned Pokémon roll individually. Ties use stable lexicographic slot ID order (application convention). Action and bonus action are shared per slot; walking movement and reactions are per actor. Reactions reset at the actor's next turn. Manual initiative uses slot IDs and one physical die per slot. Setup requires two opposing living active Pokémon sides. Register trainers before their Pokémon.

This is a lifecycle foundation, not an authorized command dispatcher. Caller must validate identity, species and instance data, legal targeting, reaction triggers, movement modes and distances, and persist state and logs atomically. Switching, damage, fainting, victory detection, status effects, special action economy, trainer-only battles, and full event history are deferred. Completion is an explicit administrative transition, not automatic victory. RNG state must remain server-private. Do not pass untrusted serialized encounter objects directly into these functions.
