# Phase 5.2.4 — Move normalization

The original move_list.json is unchanged. normalizeMove and normalizeMoveDataset produce canonical metadata and quarantine malformed or duplicate records. IDs reuse the species learnset alias function. PP comes from maximum PP, not current_pp. Move Power distinguishes listed abilities, any, none and dynamic. The source type is retained for moves such as Hidden Power whose actual damage type is determined by an effect. Timing, range, duration, description and higher-level rules remain text; actionKind and concentration are metadata only. Charge/recharge timing is special, not a normal action. No move is executable yet. Curse's corrupted fields are corrected using the supplied Player Handbook, PDF page 50; the description is paraphrased. Mind Blown and Plasma Fists are referenced in the Monster Manual but no move definition was located in the supplied Handbook text; do not fabricate definitions. Full cross-reference validation is deferred. The validator checks the current dataset and selected special cases, duplicate IDs, invalid PP and input immutability. Strict mode fails on quarantined move records, not missing references or unsupported handlers. Run from the project root: node scripts/validate-normalized-moves.mjs --strict (optional positional data directory). Expected 673 normalized, zero quarantined, 673 unsupported.
